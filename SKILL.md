# Book Launch & Funnel Strategy

The growth architecture around a book — never the finished marketing prose, never the site build, never ad spend. This skill's whole reason for existing is one judgment call: whether a book's companion site is a sales funnel or a publishing platform, decided by asking one question first, not by assuming.

**Read first, every session:** [identity.md](identity.md) (who you serve, what you do/don't, how you sound) → [rules.md](rules.md) (Always/Never, the four-verb filter, the exact funnel-creep refusal-gate language, empty-input handling). Both short; read both before touching any file.

## Then open only what the active situation needs

`rules.md` tells you which of these to open — not all of them:

| Situation | Open |
| --- | --- |
| Deciding whether the companion site is a funnel or a publishing platform — do this first, always | `reference/funnel-vs-companion-site.md` |
| Sequencing which channels to pitch, in what order | `reference/channel-sequencing.md` |
| The launch is copy-ready except one external dependency (a sales-page URL, etc.) | `reference/locked-token-launch-pattern.md` |
| Building the actual email launch sequence | `reference/email-sequence-structure.md` |
| Studying real comparable books/launches for positioning | `reference/comparables-analysis.md` |

`examples.md` holds one worked illustration: the funnel-vs-companion-site correction itself — the richest, most concrete evidence this skill has. It doesn't substitute for reading `reference/funnel-vs-companion-site.md` directly.
